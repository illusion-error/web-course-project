# 个人博客：从零到交付的执行清单

> 当前主方案。替代旧规划中“先学习、先做静态版、以后再决定后端”的执行路线。
> 用户已确认：有 HTML、前后端与数据库基础，老师允许 Codex 辅助，同时需要准备考研。
> 本文件是待执行的工作单；所有复选框保持未完成。网站开发、测试、部署没有因文档完成而完成。

## 直接确定的结果

做一个单作者个人博客：你在 `/admin/` 登录、写文章、保存草稿、发布；读者访问首页和文章详情，按关键词与分类找文章，在本机收藏。发布文章不修改 HTML、不重新部署代码。

固定技术栈：Django 5.2 LTS 最新兼容补丁 + Django 模板 + 原生 CSS/JavaScript；本地 SQLite，正式环境 PostgreSQL；WhiteNoise 提供静态资源，Linux 生产环境使用 Gunicorn。不引入 Vue、REST API、Docker、自建登录系统。这个选择是为了把维护对象控制在一套应用内。

首版正文用纯文本和分段显示，确保粘贴文章即可发布。Markdown、图片上传、评论、开放注册、多作者、邮件、统计、全文搜索引擎、定时发布均延期。课程若有新增硬要求，再增加对应功能。

预计学生主动投入：初版 12–20 小时，分 4–6 次完成；账号、网络、付费与部署问题另留 2–4 小时缓冲。估计不包括 AI 运行等待，也不保证固定用时。上线后每周 30–60 分钟用于真实内容更新、检查与提交。无需为了九周课程把能提前完成的功能拖九周。

## 产品边界：做完这些就能交付

| 地址 | 页面与行为 | 数据来源 |
| --- | --- | --- |
| `/` | 博客名、简介、最新 5 篇文章、全部文章入口 | 数据库公开文章 |
| `/posts/` | 每页 8 篇；搜索、分类筛选、上一页/下一页 | 数据库查询 |
| `/posts/<slug>/` | 标题、分类、发布日期、正文、收藏按钮 | 数据库中的一篇公开文章 |
| `/saved/` | 本浏览器收藏；清空或移除；解释保存范围 | localStorage ID + 服务端公开文章查询 |
| `/about/` | 作者简介、站点介绍、GitHub 链接 | 模板中的自有内容 |
| `/admin/` | Django 内置管理站点；分类和文章增删改、草稿/发布 | 数据库 |
| `/health/` | 部署健康检查；简单成功响应，不暴露配置 | 应用状态 |
| 不存在地址 | 友好 404 与返回首页 | 错误模板 |

导航只有：首页、文章、收藏、关于。不另外做项目展示模块。首页不写无法证明的访问量或文章统计。

页面风格默认：浅色背景、深色正文、一个强调色；桌面内容最大宽约 1040px、正文约 70ch；手机一列；系统字体；无远程字体、复杂动画和装饰性大图。你可以提供一个参考图调整，但不因缺少参考图阻塞第一版。

## 出问题时直接这样处理

| 症状 | 首先检查 | 交给 Codex 的明确任务 |
| --- | --- | --- |
| 本地打不开 | 终端是否运行、端口、报错 | 复现启动失败，定位首个异常并修复，重新启动验证 |
| 有页面但没有样式 | Network 静态资源 URL、collectstatic、WhiteNoise | 修复生产静态资源路径，验证 CSS 返回正确内容 |
| 后台能写，前台看不到 | status、published_at、查询范围 | 跟踪此文章记录到公开查询，不要直接取消权限过滤 |
| POST 403 | CSRF 令牌、可信来源、HTTPS/代理 | 修复来源与令牌配置，不关闭 CSRF 中间件 |
| 重部署文章消失 | 实际数据库连接是否 PostgreSQL | 检查是否错误使用临时 SQLite，先恢复数据再修正配置 |
| 收藏丢失 | 是否换浏览器、私密模式、存储被禁用 | 核实本地保存范围与异常反馈，不默认扩展为账号系统 |
| 线上访问慢 | 休眠、数据库区域、服务日志 | 先确认平台休眠与区域，再做具体优化，不直接加缓存体系 |

## 达到 100% 的判定

“100%”是交付完成度，不是课程分数保证。只有 0–7 批次所有适用项目完成，或明确注明并接受删减，才算结束。

不可删除：后台真实发文、公开读取、草稿保护、搜索/分类、响应式、一个清晰 JS 交互、线上 HTTPS、数据持久化、必要测试、README 与真实过程记录。

时间紧优先删除：Markdown、图片上传、额外动画、标签、浏览量、自定义域名。减少文章篇数到 3 篇；不靠删安全检查或存储持久化节省时间。
