# 今晚看什么：课程实施计划

依据：用户提供的完整正式课程要求。范围：六部动漫精选指南。当前仅有内容底稿和未完成的旧 Django 初稿；本文件中的任务均待执行，不是完成报告。

## 1. 固定方案

采用 HTML + CSS + 原生 JavaScript，多页静态网站。无需 Django、数据库、登录、API、后台、Node 构建工具。旧 Python 文件暂不删除，但不纳入网站构建、发布目录或本次验收。之后只维护 `site/` 中的前端。

作品：葬送的芙莉莲、摇曳露营△、比宇宙更远的地方、排球少年!!、间谍过家家、夏目友人帐。

目标访客：想找下一部动漫、需要简短无剧透推荐的观众。

核心流程：首页 → 题材/心情筛选 → 作品详情 → 收藏 → 想看清单。

不做：视频播放、评论、账号、真实评分、实时排行榜、实时连载状态、联网推荐、管理后台。第一版用文字卡片和自制 CSS 图形，不依赖未获授权的海报或外链图片。

## 2. 要求对应表

| 教师要求 | 实现 | 验收证据 |
| --- | --- | --- |
| 至少四页、有导航 | 首页、发现、想看、关于，外加六个独立详情页，共十页 | 页面清单、逐个打开及导航测试 |
| 自己的内容 | 自行确定选片、分类与推荐依据；重述事实、注明来源；审阅 AI 文案 | 内容决策记录、来源表、修改提交 |
| 语义与可访问性 | landmarks、标题层级、按钮/链接区分、label、键盘焦点 | 手动键盘测试、HTML 检查 |
| 手机可用 | 移动优先布局、可换行导航和卡片 | 360/768/1440px 截图及真机记录 |
| 至少一个交互 | 搜索/筛选为必做；收藏为第二个功能 | 正常/空结果/刷新测试 |
| 真实线上地址 | 发布 site/ 到静态托管，HTTPS 无登录可访问 | 公网 URL、手机流量访问记录 |
| 学期真实 Git 过程 | 实际开发时提交并记录，每周有实际进展 | git log 与开发日志对应 |

正式评分：过程 20%、项目 40%、笔试 25%、答辩 15%；总分 0–100，60 分及以上通过。过程不能靠一天拆大量 commit 补造。

上面是将创建的目标文件，不声称现已存在。顶层页面链接采用 `discover.html` 等相对路径，详情页回首页采用 `../index.html`，避免部署子目录后根路径失效。

| 页面 | 必须放的内容 | 必须工作的操作 |
| --- | --- | --- |
| 首页 | 站点目的、三组专题、作品入口 | 导航、专题到相应筛选结果、详情链接 |
| 发现 | 六张卡片、名称搜索、题材与心情筛选 | 条件联合筛选、结果数、清空条件 |
| 六个详情 | 中文/日文名、简介、推荐理由、适合谁、提醒、观看起点、来源 | 收藏/取消、返回列表、打开来源 |
| 想看 | 收藏列表与真实空状态、浏览器保存范围 | 移除、清空确认、刷新保留 |
| 关于 | 站点目的、选片方法、内容来源与 AI 使用说明 | 导航和已有公开链接 |

首版不实现“已看”状态，避免超出最低必要范围。上一份内容包中的相关按钮文案留作扩展，本计划优先。没有功能的入口直接省略，不展示“开发中”按钮。

## 4. 执行批次与完成条件

### A：内容与结构（约 1–2 小时）

- [ ] 在 `docs/CONTENT-DECISIONS.md` 记录目标访客、六部作品的选择理由、分类依据和 AI 使用方式。
- [ ] 学生逐条读完六部内容，能解释推荐理由；没有亲身观看依据的内容保持“编辑推荐”，不改成“我的观后感”。
- [ ] 核对题材、心情词与页面筛选一致；移除《我推的孩子》所有入口与数据，加入夏目友人帐。
- [ ] 创建十个 HTML 页面，放入正文；每页有不同 title、一个主要 h1、header/nav/main/footer。
- [ ] 所有页面加相同主导航，当前位置用 aria-current；详情页放面包屑导航。
- [ ] 每个页面在无 CSS、无 JS 时仍能阅读主体；作品列表直接写入 HTML，避免只有脚本才显示内容。

完成：十个页面可以互相导航，无空白正文、假链接、复制未改的标题。实际提交例：`feat: add anime guide pages and original editorial content`。

### B：布局与可访问性（约 2–3 小时）

- [ ] 一个公共 CSS；定义颜色、间距、字体、内容宽度；正文至少 16px、行高约 1.6–1.8。
- [ ] 手机一列；较宽视口两列/三列，不能强制固定宽度撑破手机。
- [ ] 导航优先换行展示，不为四个导航项增加汉堡菜单复杂度。
- [ ] 每页增加“跳转到正文”链接；使用真实 a/button/input/select，不用 div 模拟按钮。
- [ ] 输入和下拉框关联 label；焦点可见；状态不只靠颜色表达。
- [ ] 普通文字对比度以至少 4.5:1 为目标；200% 缩放无内容遮挡。
- [ ] 有意义图片若后续加入，使用 alt；装饰图形不增加朗读噪声。
- [ ] 360、768、1440px 和实际手机逐页检查，无横向溢出、截断标题、点不到的控件。

完成：保存首页、发现、详情在手机与桌面的截图，记录发现并修复的真实问题。不要假写“已通过”。

### C：搜索与筛选（约 1–2 小时，满足交互硬要求）

- [x] 名称搜索匹配中文/原名，去首尾空格、英文忽略大小写。
- [x] 题材与心情筛选共同生效；结果数随之更新，无结果显示清除筛选入口。
- [x] 首页专题使用 `discover.html?mood=想放松` 等约定参数；进入列表时读取并应用。
- [x] 更新地址参数时保留有效条件；刷新与后退正确恢复状态，非法参数回到默认值。
- [x] 动态结果提示使用 aria-live="polite"，不抢走键盘焦点。
- [x] 无 JS 时显示全部作品及“筛选需要启用 JavaScript”提示，不假装筛选生效。

完成：空搜索、中文名、英文名、无匹配、组合条件、清空、刷新、返回均测试通过。

验收细节及验证范围见 [批次 C 记录](BATCH-C-RESULTS.md)。

### D：想看清单（约 1–2 小时）

- [x] catalog.js 保存六部作品的稳定 ID、名称、详情路径；与 HTML 名称一致。
- [x] localStorage 仅保存合法 ID 数组，键名固定 `anime-watchlist-v1`。
- [x] 加入/取消后按钮文字及 aria-pressed 更新，同一作品不重复保存。
- [x] 想看页从目录数据生成卡片；未知 ID 忽略，不信任本地存储中的 HTML。
- [x] 取消一部、全部清空、取消清空都可用；清空有确认。
- [x] JSON 损坏、存储不可用时给明确反馈，继续允许浏览作品。
- [x] 显示“仅保存在当前浏览器”，不承诺云同步；初次访问显示真实空状态。

完成：加入两部 → 刷新 → 移除一部 → 清空取消 → 清空确认；换浏览器初始为空。

验证范围见 [批次 D 记录](BATCH-D-RESULTS.md)。

### E：测试与上线（约 1–2 小时，不含托管账户阻塞）

- [ ] 本地运行 `python -m http.server 8000 --bind 127.0.0.1 --directory site`，不双击 file:// 检查存储行为。
- [ ] 检查十个页面所有内部 href、静态文件路径和作品来源链接；外部异常明确修正或移除。
- [ ] 检查 Console 无脚本异常，Network 无缺失资源；页面无空占位、虚构数字和失效控件。
- [ ] 用 HTML 校验器检查结构，再人工验证 Tab/Enter 操作；自动分数不代替实际使用。
- [ ] 只发布 `site/`，不上传 .env、.venv、Python 后端或私有文档。
- [ ] 使用支持静态目录的托管平台及默认域名，配置输出目录为 site；具体平台在发布时落实，不因此引入数据库。
- [ ] 若选 GitHub Pages，先确认私有仓库的套餐资格；不为开 Pages 擅自把仓库改公开。
- [ ] 部署后在手机移动网络及未登录浏览器打开首页、六个详情直链；逐页刷新不返回 404。
- [ ] 线上再检查筛选和收藏。本地与公网不同来源，收藏不自动迁移属于预期。
- [ ] README 写入实际公网地址、运行方法、目录说明、交互与限制；没有部署成功前不填假地址。

完成：真实公开 HTTPS 地址可用；测试报告写明日期、浏览器、操作、实际结果、修复记录。

### F：提交、笔试、答辩（约 1 小时准备，之后持续维护）

- [ ] 交付：线上地址、仓库访问方式、README、测试报告、内容决策、AI 使用记录。
- [ ] 清理只针对自己创建的无用文件；旧工程不进入发布目录，不破坏其他未提交工作。
- [ ] 检查 git log：每个提交能对应真实功能、修复或内容调整；已有旧选题历史保留。
- [ ] 功能通过后创建最终标签，后续修复继续正常提交。
- [ ] 准备五分钟演示：30 秒用户需求；90 秒筛选/详情/收藏；60 秒手机与可访问性；60 秒实现选择；60 秒真实问题、修复及 AI 判断。
- [ ] 能解释 filter.js 的条件判断、storage.js 的序列化与异常处理、HTML 链接和 CSS 断点。
- [ ] 笔试练习：各找一处 HTML、CSS、JS 错误，说明现象、原因、所属层、修复与验证方式，不背答案代替理解。

## 6. 过程分与内容要求：不能用技术替代的部分

AI 辅助是允许的，但此前“你不用再看就能直接交”的表达不能作为课程合规保证。正式要求明确考察学生判断和解释能力：六篇现有文案可以作为底稿，学生必须读懂、认可或修正，并记录为何这样选片、分类和推荐。没有实际完成这些动作前，不勾选“自己的内容已验收”。资料引用不能冒充原创，AI 文案也不能伪装成真实观后感。

每次实际工作结束提交一次有意义的变化，附简短日志：做了什么、为什么、怎么验证、AI 做了什么、自己改了什么。之后每周根据实际反馈完善内容或修复问题；没有代码变化就如实记录内容/测试，不为凑次数制造空改动。

若距离截止只剩几天，可以先完成可用网站，但不能保证补回过去缺失的学期过程分。不得倒签日期、生成虚构周记或把一个晚上拆提交宣称为整学期开发。
